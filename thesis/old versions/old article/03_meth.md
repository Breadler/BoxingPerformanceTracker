III.	METHODOLOGY
The pipeline proceeds in five stages: automatic pose extraction from training video, manual labelling of punch windows from the extracted data, algorithmic conversion of pose data and labels into an engineered training dataset, training of a Random Forest classifier, and application of that classifier to new user footage. Fig. 1 illustrates these stages, the scripts that implement them, and the data artifacts passed between them; the remainder of this section describes each stage in turn.
Fig. 1.	Methodology Flowchart
A.	Input
The training pipeline takes boxing video clips drawn from the UCF101 action recognition dataset as input, rather than a controlled, self-recorded video set. Because UCF101 clips were not collected specifically for this project, they vary in camera angle, lighting condition, background, recording quality, and frame rate; these variations are not controlled during data collection and are treated as a characteristic of the dataset rather than a confound to be eliminated. Because frame rate varies across clips, a fixed number of frames does not correspond to a fixed amount of real-world time, which motivated a shift from frame-count to time-duration (millisecond-based) windows for both training and prediction, described in the labelling algorithm and inference subsections below. A separate, single user-recorded or uploaded boxing video is used at inference time, processed through an equivalent but independent extraction path so that the training dataset and live predictions never share code paths that could introduce data leakage.
B.	Automatic Pose Landmark Extraction
A python file, pose_extractor.py, processes each training video frame by frame using MediaPipe Pose Landmarker (models/pose_landmarker_lite.task) to extract 3D body landmarks. For every frame, it records a video identifier, frame index, timestamp, a pose-detected flag, and the coordinates and visibility values of each landmark, writing the result to data/pose_frames.csv. The same script can additionally generate an annotated review video with the detected pose skeleton and the frame number drawn directly on top of the footage; this annotated video is what a human reviewer subsequently watches to identify punches. Another file, extract_user_pose_frames.py mirrors this extraction logic for a single new user video, producing an equivalent but unlabelled data/user_pose_frames.csv used later for prediction.
C.	Manual Labelling of Punch Windows
Punch moments are identified by a human reviewer, with boxing knowledge and experience, watching the annotated, frame-numbered review video. For each punch observed, the reviewer records the video identifier together with the start and end frame of the punch, building punch_windows.csv. This file therefore contains one row per manually identified punch, expressed in terms of frame numbers rather than raw pose coordinates. Frame-based labels are automatically converted to millisecond ranges downstream using each frame's timestamp_ms, so the manual review workflow itself is unaffected by the frame rate of the source video.
Because incorrect or inconsistent manual labels directly reduce downstream model accuracy, audit_punch_labels.py is run over punch_windows.csv before it is used for training. The audit checks for missing video identifiers, invalid or reversed start/end frames, punch labels that are implausibly short or long, and labels that reference frames outside the range actually covered by the corresponding pose-frame data. This functions as an automated quality-control step on top of the manual labelling process, rather than a replacement for it.
D.	Labelling Algorithm and Feature Engineering
build_training_csv.py performs the core labelling and feature-generation step, combining the frame-level pose data (data/pose_frames.csv) with the manually labelled punch intervals (data/punch_windows.csv). The script builds fixed-duration windows defined in milliseconds (--window-ms), so that a punch occupies the same amount of real-world time in the resulting dataset regardless of the source clip's frame rate. Positive (punch) windows are anchored to the end of the labelled interval by default (--positive-anchor end), preserving the punch's impact frame at a fixed position within the window rather than letting it fall at an arbitrary offset. Negative (no_punch) windows are sampled using a millisecond-based stride (--negative-stride-ms) rather than a frame-based stride, for the same reason. Frame-based manual labels are converted to millisecond ranges using each frame's timestamp_ms before windowing, so this change is transparent to the manual labelling process described above.
For each window, the script computes motion-based and body-relative features rather than relying on raw landmark coordinates alone: wrist and elbow velocity, wrist position relative to the shoulder, arm position relative to the body centre, the change in shoulder-to-wrist distance, and the change in wrist forward extension. These features are chosen because a punch is not simply movement in general, but a specific pattern of arm extension relative to the body, and raw coordinates alone do not capture that distinction well. The result is written to training.csv, the final supervised dataset used for classifier training.
E.	Classifier Training
	train_random_forest.py trains a Random Forest classifier on training.csv to distinguish punch from no_punch windows. Alongside the trained model (models/random_forest.joblib), the script saves the exact list of feature columns used during training, ensuring that later prediction on new footage uses an identical feature structure.
F.	Inference on New Footage
For a new user video, extract_user_pose_frames.py produces user_pose_frames.csv in the same format as the training pose data. predict_punches.py then slides the same fixed-duration, millisecond-based window used during training across this data, computes the identical set of features, and applies the trained Random Forest model to classify each window as punch or no_punch. Per-window predictions are written to user_window_predictions.csv, and overlapping or adjacent punch predictions are merged by time into data/predicted_punch_windows.csv, which reports both millisecond time ranges and the corresponding frame numbers, from which a final estimated punch count and punch timing are derived.
G.	Evaluation Criteria
This paper evaluates the labelling algorithm, focusing on the quality and correctness of the manually generated labels. The punch labels serve as the ground truth for Random Forest training, so incorrect or inconsistent annotations could negatively affect classifier performance. The evaluation therefore verifies annotation correctness, dataset completeness, and label consistency, using automated validation through audit_punch_labels.py together with manual inspection of the annotated videos generated during pose extraction.
Because a single annotator carried out all labelling, and the boxing clips are drawn from the UCF101 dataset rather than recorded under controlled conditions, this evaluation does not report inter-rater reliability or make claims about controlled recording conditions. Instead, it provides measurable evidence that the labelling process itself is correct and internally consistent. The criteria used for this evaluation are as follows.
•	Pose Detection Coverage: percentage of frames with a successfully detected pose (pose_detected = True); high coverage with minimal missing frames is expected.
•	Label Completeness: manual comparison between annotated videos and punch_windows.csv to confirm no visible punch was left unlabelled.
•	Frame Boundary Accuracy: manual frame-by-frame inspection confirming that labelled start/end frames closely match the actual punch motion.
•	Label Integrity: audit_punch_labels.py validation that every label has a valid video ID and frame range.
•	Frame Range Validation: automated comparison with pose_frames.csv confirming labelled frames exist within the extracted pose data.
•	Punch Window Validation: audit_punch_labels.py duration checks (in milliseconds) flagging unusually short or long punch intervals.
•	Duplicate Label Detection: manual review and audit script confirming identical punch intervals are not recorded more than once.
H.	Evaluation Procedure
The evaluation begins after pose landmarks have been extracted using MediaPipe Pose Landmarker. Annotated review videos containing the detected pose skeleton and frame numbers are generated to assist the labelling process. These videos are manually reviewed to identify the start and end frame of each punch, and the corresponding annotations are stored in punch_windows.csv.
Once labelling is complete, the generated labels are validated using audit_punch_labels.py, which performs a series of automated integrity checks: verifying video identifiers, validating frame ranges, detecting labels outside the available pose-frame sequence, and identifying punch windows with abnormal durations, now reported in milliseconds so that duration checks remain meaningful across clips with different frame rates, and working whether a label is expressed as a frame range or a millisecond range. Any issues detected are corrected before the labels are used to generate the final training dataset.
Because the boxing videos are drawn from the UCF101 dataset, the recordings vary in camera angle, lighting condition, background, and recording quality, and these variations are not controlled during data collection. This may affect the accuracy of pose landmark extraction. Consequently, the evaluation focuses on verifying the correctness of the annotations derived from the extracted landmarks, rather than on assessing recording consistency across videos.
This evaluation approach is appropriate for the present methodology because it validates the quality of the manually created ground-truth labels, which are the foundation of the supervised learning process, without making unsupported claims about inter-rater reliability or controlled recording conditions, while still providing measurable evidence that the labelling process is accurate and suitable for subsequent Random Forest training.
